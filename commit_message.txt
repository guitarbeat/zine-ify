🧹 [Refactor Toast.show into smaller private methods]

🎯 **What:**
The `show` method inside `src/components/Toast.js` was overly long and handled multiple responsibilities including DOM element creation, appending elements, managing auto-removal loops, and executing CSS animations. It has been broken down using the "Extract Method" refactoring technique. Three new private methods were introduced: `_buildToastElement`, `_setupAutoClose`, and `_animateIn`.
Also updated pnpm-lock.yaml version using `pnpm install --no-frozen-lockfile` to resolve CI installation errors due to missing overrides keys for current `packageManager: pnpm@10.27.0`.

💡 **Why:**
This improves the readability, maintainability, and code health of the Toast component. The `show` method now clearly acts as an orchestrator, while the granular implementation details are nicely tucked away within helper methods, adhering to the Single Responsibility Principle. Furthermore, resolving the lock file prevents pipelines from breaking while fetching dependencies.

✅ **Verification:**
1. The method logic string replacement was accurately verified manually.
2. The code was styled and validated successfully using `npx eslint src/components/Toast.js --fix`.
3. The Playwright tests (`toast_xss.spec.js`) successfully passed without encountering regressions. Other UI failures present across the E2E suite are pre-existing issues involving page load timeouts in tests unrelated to these modifications.
4. The change was reviewed by the Code Review agent.

✨ **Result:**
The toast component continues functioning with unchanged public functionality, but its internal implementation is much easier to maintain, read, or extend in the future. CI should pass properly.
