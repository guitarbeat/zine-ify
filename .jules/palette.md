## 2024-04-14 - Icon-only modal close buttons missing ARIA labels
**Learning:** Icon-only modal close buttons (like the 3D preview and page picker close buttons) often miss `aria-label` and `title` attributes, making them inaccessible to screen readers and lacking tooltips for mouse users. Even dynamically generated modals (like the zoom preview modal in `ModalManager.js`) need these attributes explicitly defined in their HTML template strings.
**Action:** Always ensure that icon-only interactive elements (`<button>`, `<a>`) have clear, descriptive `aria-label` and `title` attributes, regardless of whether they are hardcoded in the main HTML file or generated dynamically via JavaScript.

## 2024-04-14 - Dynamically Generated UI Components Require Explicit Accessibility Attributes
**Learning:** Dynamically created UI components in JavaScript (like `document.createElement('button')`) often miss basic accessibility attributes compared to static HTML components. Specifically, icon-only buttons created via DOM manipulation (e.g., in `ActionOrb.js` or `UIManager.js`) can easily omit `aria-label` or `title` attributes, making them inaccessible to screen readers and lacking tooltips for mouse users. Similarly, input elements like `<input type="range">` in `FluidSlider.js` might not have associated labels or `aria-label`s when created dynamically.
**Action:** When creating UI components programmatically via JS, explicitly set `aria-label` and `title` attributes (using `element.setAttribute()` or property assignment) for any icon-only interactive elements or inputs to ensure parity with accessible static HTML components.
