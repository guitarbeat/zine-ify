## 2026-06-23 - Phantom Focus in Hidden Overlays
**Learning:** When converting hover-only elements (like a "Remove" hint `<div>` using `opacity: 0`) to natively focusable semantic elements (`<button>`), relying on `opacity: 0` is insufficient. The element remains in the accessibility tree and tab order, creating phantom interactive elements. Additionally, pairing this with `pointer-events: auto` to enable clicking can block interactions on underlying empty placeholders.
**Action:** When a semantic interactive element is visually hidden and inactive, explicitly remove it from the accessibility and interaction layer using `display: none` (e.g., `.parent:not(.is-active) .button { display: none; }`) instead of relying solely on `opacity` or `pointer-events`.
