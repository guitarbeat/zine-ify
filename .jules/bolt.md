## 2026-04-16 - Handling Errors in Concurrent Promise Pools
**Learning:** When refactoring a sequential `for` loop with `await` into a concurrent sliding-window worker pool using `Promise.race` and a `Set` of active promises, simply catching errors on the individual promises to prevent `Promise.race` from throwing is insufficient. If a promise rejects after `Promise.race` resolves (because another promise finished first), and its error is swallowed or it's removed from the tracking set, it will lead to an `UnhandledPromiseRejection` or silent failures.
**Action:** Track *all* spawned promises in a separate array. Use a `hasError` flag to break the main loop and prevent pending tasks from doing further work. Let the original promise rejections propagate by mapping them in the tracking array (e.g., `allPromises.push(promise.catch((e) => { hasError = true; throw e; }))`), and ensure the function finishes with `await Promise.all(allPromises)` to safely collect and throw any errors that occurred in the background.
