## 2024-05-18 - Client-Side DoS via Unbounded Grid Size Manipulation
**Vulnerability:** The application allowed users (or malicious scripts) to dictate the dimensions of a generated grid layout (Rows x Columns) strictly relying on HTML `min` and `max` attributes for validation. Bypassing these attributes in the DOM allowed an attacker to input arbitrarily large values, which were then multiplied to determine the loop count for injecting new grid cells (DOM elements), leading to a Denial of Service via memory exhaustion and thread-locking.
**Learning:** HTML-level validation constraints (`min`, `max`, `step`, `required`) provide a better UX but offer zero security against a client-side attacker. Any logic downstream that consumes these values to dictate looping iterations or memory allocations is susceptible to client-side DoS if those values are not sanitized or clamped again in JavaScript.
**Prevention:** Strictly re-validate and clamp numerical values in JavaScript before they influence logic involving recursion, loops, memory allocation, or DOM manipulation. Specifically, inputs controlling array sizes or loop lengths must always have safe upper boundaries enforced in code (e.g., `value = Math.max(min, Math.min(max, value))`), and UI inputs should be actively synced back to reflect those clamped constraints.
