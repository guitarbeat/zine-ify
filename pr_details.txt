Title: 🛡️ Sentinel: [High] Fix Unsafe Sanitization Fallback

Description:
🎯 **What:** The vulnerability fixed
The `sanitizeHTML` utility function previously relied on a custom DOM parser using `template.innerHTML` with a custom node-filtering loop. While it attempts to construct a safe tree by copying specific tags, custom DOM-based HTML sanitizers that interact with `innerHTML` are inherently prone to subtle browser-specific mutation XSS (mXSS) vectors or attribute bypasses compared to heavily vetted, battle-tested libraries.

⚠️ **Risk:** The potential impact if left unfixed
If an attacker successfully formulates a payload that bypasses the manual traversal logic (e.g., via malformed nested tags or attribute smuggling), they could achieve Cross-Site Scripting (XSS). This could lead to session hijacking, unauthorized actions on behalf of the user, or client-side denial of service, particularly anywhere user-controlled strings (like file names or toast messages) are rendered dynamically.

🛡️ **Solution:** How the fix addresses the vulnerability
Replaced the custom HTML sanitization logic entirely with DOMPurify (`DOMPurify.sanitize`). DOMPurify is actively maintained to address mXSS edge cases. The fix maintains identical functional behavior by configuring DOMPurify to return a `DocumentFragment` (`RETURN_DOM_FRAGMENT: true`) and restricting the allowed tags to the exact same subset previously permitted (`ALLOWED_TAGS: ['b', 'strong', 'i', 'em', 'u', 'br', 'code', 'span']`).

Verification:
- Tested XSS payloads using Playwright against filename inputs and Toast configurations (tests pass).
- Unit tests run against `sanitizeHTML` to guarantee functionality remains functionally identical (no regression).
